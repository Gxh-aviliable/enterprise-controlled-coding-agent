### 22:51 - 按 1M 模型窗口重整压缩与累计 token 预算

- 修改内容：
  - 将默认 `MODEL_CONTEXT_WINDOW_TOKENS` 从 128,000 调整为 1,000,000，与当前默认 `deepseek-v4-flash` 的官方模型窗口对齐。
  - 取消 legacy `TOKEN_THRESHOLD=500000` 对正常运行时压缩阈值的隐式封顶；自动压缩现在唯一由 `MODEL_CONTEXT_WINDOW_TOKENS × CONTEXT_COMPRESSION_RATIO` 计算，默认为 800,000 tokens。`TOKEN_THRESHOLD` 只保留为缺失模型窗口时的兼容回退。
  - 为 `TASK_TOKEN_BUDGET` / `SESSION_TOKEN_BUDGET` 定义 `0=关闭该级累计熔断`，预算大于 0 时才做耗尽检查，但 usage 始终继续统计；运行时校验允许 0 并拒绝负数。
  - 没有机械地同时取消两级预算：会话级设为 0，避免长会话因历史累计量被中断；单任务从 1,000,000 提高到 4,000,000，保留大约 5 次近 800K 工作集调用的熔断能力。轮次、工具、超时及管理员日/月额度继续生效。
  - 同步示例配置、README 和项目 walkthrough，明确“单次模型窗口”与“跨轮次累计预算”的区别。
- 修改原因：原配置将模型窗口保守设为 128K，有效压缩阈值只有 102.4K；即使只将窗口改为 1M，旧 `min(TOKEN_THRESHOLD, window × ratio)` 仍会在 500K 提前压缩。另一方面，同时取消任务与会话熔断会让 20 轮近满上下文产生千万级累计输入，不符合受控 Agent 的故障收敛目标。
