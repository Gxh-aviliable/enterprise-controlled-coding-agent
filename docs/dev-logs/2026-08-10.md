### 01:38 - 实现可恢复的安全边界 Pause/Continue

- 修改内容：
  - 将任务状态机扩展为包含 `paused` 的七态模型，并定义
    `running → paused → running/cancelled` 的合法迁移。
  - 新增 Redis 暂停控制键和恢复互斥锁，键和值均绑定
    `user_id + session_id + trace_id`，重复 Pause 幂等、重复 Continue 被拒绝。
  - 在 LangGraph 的模型调用、工具派发、工具执行、工具结束、验证、压缩和
    finalize 前设置安全边界；gate 节点先提交 `paused` checkpoint，再由独立
    `user_pause` 节点执行 typed `interrupt()`。
  - 新增 Pause、状态查询和 Continue API；HITL `tool_confirmation` 与
    `user_pause` 使用不同恢复入口并互相拒绝，Stop 继续表示不可恢复的 Cancel。
  - SSE 增加 `task_started`、`paused` 和 `cancelled` 控制事件；Trace 增加
    `pause_requested/task_paused/resume_requested/task_resumed` 及暂停次数、恢复次数、
    暂停耗时指标。
  - 前端增加 Pause、Continue、Stop 独立控制，展示 Pausing、Paused、Resuming
    状态，并可在刷新后从服务端恢复已经进入 `paused` 的 checkpoint。
  - smoke test 增加 Pause 图节点和三个控制 API 的离线检查。
- 修改原因：原 Stop 只会进入 `cancelled` 终态，RedisSaver 虽支持 HITL checkpoint，
  但没有用户主动暂停协议；需要实现真实可恢复暂停，同时避免暂停与审批、取消串线。

### 02:52 - Stop 取消上下文隔离回归测试

- 修改内容：
  - 新增真实 `StateGraph(AgentState) + InMemorySaver` 回归，覆盖 SSE 已 abort、
    请求 Stop/Cancel、重复 Cancel 和同 session 下一次模型调用的完整链路。
  - 断言被取消轮次由 `human -> ai cancellation tombstone` 闭合，下一条
    用户消息不会与旧未完成消息形成 `human -> human` 并被模型合并回答。
  - 新增 MySQL 持久化竞态回归：已是 `cancelled` 的 assistant 行不得被晚到的
    SSE `interrupted` 状态回退，重复取消不得追加多个 tombstone。
  - 前端新增运行中 Stop 断言，确认先 abort SSE，再用精确 `trace_id` 请求
    后端 Cancel，并在成功后恢复输入。
- 修改原因：防止被 Stop 的未完成用户请求与同会话下一个请求一起交给 LLM，
  导致一次回答两个问题或错误判断“上一问”。
