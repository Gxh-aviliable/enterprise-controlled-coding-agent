### 16:56 - 将 Shell HITL 改为参数级风险确认

- 修改内容：
  - 将原先仅按工具名判断的确认策略改为读取具体 `bash/background_run` 参数并解析风险。
  - `safe` 命令（如 `pwd`、`ls`、`pytest`、`git status`、常规构建）自动执行，不再触发 LangGraph interrupt。
  - `review` 命令（如 `git commit`、`npm install`、复合命令）继续要求人工确认。
  - `dangerous` 命令不再弹出可批准窗口，而是直接进入执行器并由 Shell 策略拦截，Trace 记录为 `policy_blocked`。
  - 前端确认弹窗展示风险徽标，并将 `Approve All` 改为 `Approve Current Batch`，明确批准只覆盖当前 interrupt。
  - 后台危险命令返回值改为标准 `Blocked:` 结果，避免被归类成普通工具错误。
- 修改原因：
  - 旧策略将整个 `bash` 合同静态标记为需要确认，导致每个安全命令都弹 HITL；同时 `Approve All` 的文案让用户误以为会永久批准后续调用。

### 18:14 - 修复流式生成时无法向上滚动

- 修改内容：
  - 将消息区原先每个 token/工具事件都强制滚到底部的逻辑改为“接近底部才自动跟随”。

  - 在暂停跟随时显示 `Latest` 浮动按钮，点击后滚到最新内容并恢复自动跟随。

  - `onDelta` 和工具事件持续调用 `scrollBottom()`，原实现无条件设置 `scrollTop = scrollHeight`，导致用户任何向上滚动都会被下一条 SSE 数据立即覆盖。
