### 18:52 - Pause/Continue 下线与可靠 Cancel-and-Replan 改造

- 修改内容：
  - 从 full/simple 两套 LangGraph 删除 7 组 cooperative pause gate 和 `user_pause` 节点，直接连接原目标节点；删除暂停专用状态和 Pause/Continue API/UI，保留 RedisSaver、`WAITING_CONFIRMATION`、`Command(resume)` 和历史 paused Trace 只读展示。
  - 将工具确认 resume lock 迁移到通用 `interrupt_control.py`，使用 owner token + compare-delete；增加 Redis 权威 active-trace lease、runner token/epoch/fence、exact-trace cancel tombstone 和多 worker 原子状态转换。
  - 加固 running、工具批次、LLM retry、waiting-confirmation 和首 checkpoint 前的 Stop；只有 owner 静默、checkpoint 取消、MySQL receipt 持久化且 lease 释放后才对客户端确认 `cancelled`。
  - 前台 Shell 改为 `Popen` + process group TERM/KILL，并明确返回 best-effort 结果；托管 background process 按 trace 隔离，同步轮询 Redis tombstone，使跨 worker Stop 也由真实 owner 终止进程。
  - 取消时在 MySQL 持久化 continuation receipt（原目标、完成/未完成项、修改文件、验证结果、风险）；Redis checkpoint 无历史时，从 MySQL 构建经过裁剪去重的同 Session 模型上下文，并由新 trace 的 LLM 调用重新规划。
  - 前端 Stop 改为终态确认协议：cancel 失败保持输入锁定并允许 Retry/Check status；通过 `streamEpoch + controlEpoch + trace_id` 丢弃旧 SSE/控制回调；工具确认弹窗增加真正的 `Terminate task`。
  - 新增 legacy pause 幂等启动终态化，把 `paused/pause_requested/resuming` 转为 `cancelled`，原因为 `user_pause_feature_retired`，并清理旧 Redis pause key；增加 Phase A bridge / Phase B removal 滚动部署文档。
- 修改原因：用户主动 Pause/Continue 无法提供可靠的跨 worker 执行语义，且会让旧 checkpoint 与新图拓扑互相阻塞；改为终态 Stop 后以新 trace 基于聊天历史、工作区实际状态和 receipt 重新规划。
