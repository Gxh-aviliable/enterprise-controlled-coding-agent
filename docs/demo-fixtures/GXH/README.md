# 多商品订单结算

订单系统新增了固定金额优惠券。普通订单可以结算，但混合商品、分摊尾差以及优惠后运费出现了客户投诉，需要根据以下规则排查修复。

## 业务规则

### 商品与优惠资格

- 每行商品包含 `sku`、`unit_price`、`quantity` 和 `coupon_eligible`（默认 true）。
- SKU 不可重复，单价大于零，数量为正整数；订单不可为空。
- 行金额 = 单价 × 数量。货币输入为有限非负数，单价与券面额按四舍五入保留两位小数，使用 Decimal 计算。
- 礼品卡等 `coupon_eligible=false` 商品不能使用优惠券，但仍计入商品总金额、包邮判断及实付金额。

### 优惠券分摊

- 一笔订单使用一张固定金额优惠券，默认金额为零，不再适用旧版“满 200 减 20”规则。
- 实际优惠预算 = 券面额与可优惠商品总金额中的较小值；没有可优惠商品时优惠为零。
- 在可优惠商品之间，按各行商品金额占可优惠金额的比例分摊，数量必须计入权重。
- 分摊以“分”为最小单位：先保留每行理论份额的整分，再把剩余的分按小数余数从大到小分配；余数相同按原始输入顺序分配，不按 SKU 排序。
- 每行优惠不得超过该行商品金额，各行优惠之和必须等于实际优惠预算，不得凭空增加或丢失一分钱。

### 运费与结果

- 优惠后商品总金额满 99 元包邮，不足 99 元收取 8 元运费；即使商品全部被优惠抵扣，也按此规则收运费。
- 实付金额 = 各行优惠后金额之和 + 运费。
- 保留输入商品顺序，返回每行原金额、优惠和优惠后金额，以及订单汇总。

## 客服反馈

1. 60 元普通商品与 40 元不可优惠礼品卡一起买，使用 20 元券，应优惠 20 元、运费 8 元、实付 88 元。
2. 三件各 10 元的商品分摊 1 元券，依次应分摊 0.34、0.33、0.33 元。
3. 三件各 0.05 元的商品使用 0.02 元券，优惠总额必须正好 0.02 元。
4. 105 元商品使用 10 元券，优惠后 95 元，需要 8 元运费，实付 103 元。
5. 三件各 30 元的普通商品和一张 30 元礼品卡使用 30 元券，应实付 98 元。

## 文件与运行

- `checkout.py`：输入整理、优惠分摊、运费和汇总结算，直接运行会打印第 5 个场景的结果。
- `test_checkout.py`：正常流程、金额尾差、混合商品、运费和输入校验的回归测试。

在用户工作区根目录执行（已位于 GXH 时省略 `cd GXH &&`）：

```bash
cd GXH && python checkout.py
```

```bash
cd GXH && python -m pytest -q test_checkout.py
```

需要 Python 3 和 pytest，平台执行镜像已安装 pytest，无需联网下载其他依赖。

## 修复要求

先运行测试复现并分析失败之间的关联，再修复根因；保留现有函数接口、返回字段和业务规则。不得硬编码测试数据，不得删除、跳过或弱化已有测试。可以增加必要用例，最后运行完整测试并说明修改文件、根因、验证结果及未完成事项。修改范围限定在 GXH 内。
